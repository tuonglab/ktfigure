Before you begin

Start with the question.

Write one sentence describing the finding, then order panels so the reader sees the design, the main result and the supporting evidence. Lead with the most informative view, not necessarily the most dramatic one. Label units, sample sizes, replicates and uncertainty; retain inconvenient observations and use appropriate axis scales.

Both examples below use synthetic teaching data, not real experiments. The layouts are storyboards, not screenshots or evidence of a biological effect. Follow the installation and first-plot guide before starting. For each plot, choose Plot, drag a region, load the specified CSV in Data, choose the type and columns in Plot, then click Apply. Repeat for each panel; use Select and Properties to style it.

AI-generated illustrations: Generated imagery can invent biological structures, labels or relationships, and may raise provenance or journal-policy issues. Do not treat it as scientific evidence. Verify every element with domain expertise, follow the journal's disclosure rules, and draw the simple concept panels below from your actual design instead.

Showcase 01 / Experimental biology

A treatment time course.

Story: show how a response changes over time, then inspect individual endpoints and possible relationships. Download timecourse.csv and timecourse-endpoints.csv. Each group has four fictional subjects measured at 0, 24 and 48 hours; the endpoint file has one row per subject. Values and units are illustrative.

AStudy designGroups → sampling times
BTime courseResponse over time
CEndpointIndividual observations
DBaseline vs endpointWithin-subject context
EBiomarker vs changeExplore association
FChange distributionSpread by group

Storyboard: arrange A–C on the first row and D–F on the second. Panel sizes may differ to give the main result more room.

1. Draw panel A: the experimental design

  1. Reserve the upper-left region. Draw two Rectangle outlines for Control and Treatment; select each and use Shape Properties to match colour and line width. Add a horizontal Line for time and short lines for 0, 24 and 48 h. Add circles or rectangles to mark sampling points.
  2. Use Text to place the group names, time labels and a short description of the measurement. Check that the diagram matches the actual sampling schedule and does not imply randomisation or interventions that did not occur.
  3. Text and arrowheads are not included in the current vector export. Keep a note of your labels and add them, plus any arrowheads, in a vector editor after exporting. Basic solid outlines and lines do export; inspect them in the file.

2. Build panels B–F

For each row, use the named file and set the remaining mapping fields to (none). In Properties, add the suggested axis labels and set a consistent font, style and palette.

Panel / questionPlot and mappingsWhy this view?
B · How does response change?timecourse.csv: line; X time_h, Y response, Hue group. Labels: Time (h), Response (a.u.).Shows the group trajectory. The line plot aggregates observations at each time; it does not draw each subject's paired trajectory.
C · How variable is the endpoint?timecourse-endpoints.csv: strip; X group, Y endpoint. Label Y: 48 h response (a.u.).Shows all four observations per group rather than hiding them behind a mean.
D · Does baseline matter?Endpoint file: scatter; X baseline, Y endpoint, Hue group. Label both axes in a.u.Each point represents one subject's paired baseline and endpoint; it is not a paired-line plot.
E · Is a biomarker associated with change?Endpoint file: scatter; X biomarker, Y change, Hue group. Labels: Baseline biomarker (a.u.), Change from baseline (a.u.).Shows the observations behind a possible association, not proof of causation.
F · How does change vary?Endpoint file: histogram; X change, Hue group. Label X: Change from baseline (a.u.).Illustrates a distribution view; with only four subjects per group, bins can be misleading. Prefer C for individual values and use larger samples for a distribution claim.

Interpretation: change is the 48 h value minus baseline. Line-plot uncertainty is calculated by the underlying seaborn defaults and can vary by version; verify what is shown before describing it in a legend. Do not treat repeated time points as independent subjects. Describe sample size, biological versus technical replicates and any uncertainty or statistical test in the figure legend.

Showcase 02 / Methods paper

Compare two analysis workflows.

Story: explain the benchmark, show performance across matched datasets and make the accuracy–runtime trade-off visible. Download methods-benchmark.csv. It contains fictional results for two methods on eight matched datasets; each row is one method–dataset run. Scores are illustrative, not validation of a real method.

AAnalysis workflowInput → methods → evaluation
BAccuracyIndividual benchmark runs
CTrade-offRuntime vs accuracy
DRuntimeVariability by method
EAgreementAccuracy vs agreement
FScore distributionOverlapping ranges

Storyboard: the diagram establishes what was compared before the reader encounters the benchmark results.

1. Draw panel A: the analysis workflow

  1. Draw a Rectangle for “Input datasets”, two for “Method A” and “Method B”, and one for “Evaluation”. Use Line segments to connect input to both methods and each method to evaluation. Select shapes to match their outlines and widths.
  2. Place those labels with Text as a working guide. Add a short note such as “matched datasets” only if it is true for your study. Keep the workflow simple enough to read at the final figure size.
  3. After PDF or SVG export, add the text and any arrowheads in a vector editor; these annotations are not currently exported by ktfigure. Confirm the arrows point in the correct direction.

2. Build panels B–F

Load methods-benchmark.csv for each plot and leave unspecified mappings at (none).

Panel / questionPlot and mappingsWhy this view?
B · How accurate?strip; X method, Y accuracy. Label Y: Accuracy (fraction).Shows individual runs rather than only an average.
C · What is the trade-off?scatter; X runtime_min, Y accuracy, Hue method. Labels: Runtime (min), Accuracy (fraction).Shows both speed and accuracy, including overlap between methods.
D · How variable is runtime?box; X method, Y runtime_min. Label Y: Runtime (min).Summarises the spread; with only eight runs per method, also consider a strip plot to expose all observations.
E · Do metrics agree?scatter; X agreement, Y accuracy, Hue method. Labels: Agreement (fraction), Accuracy (fraction).Checks whether two distinct metrics tell a consistent story; association does not establish equivalence.
F · How are scores distributed?histogram; X accuracy, Hue method. Label X: Accuracy (fraction).Shows score ranges; bin choice matters, especially with only eight runs per method.

Each dataset appears once for each method: the plots above do not connect matched pairs. For a paired comparison, calculate per-dataset differences with an appropriate analysis outside ktfigure and state how pairing was handled. Define accuracy and agreement, data splits, hardware and runtime measurement in the legend; avoid claiming general performance from this toy benchmark.

Design in practice

Make the comparison fair.

These schematic layouts show design choices, not actual results. The goal is to make the same evidence easier to read, not to make an effect look larger.

Uneven edges, inconsistent label sizes, crowded titles and colour without a key make the story difficult to follow.

Clearer

A Study designB Main resultC Individual valuesD Supporting result

Aligned panels, consistent hierarchy, concise labels and deliberate whitespace help readers compare the evidence.

Scientific trade-off: a truncated axis can exaggerate a difference; a bar of means can hide outliers; changing group colours between panels can suggest a false comparison. Choose a scale appropriate to the data, show individual values when feasible, and explain any transformation or axis break.

Final pass / Both showcases

Inspect at publication size.

  1. Align and label. In Select mode, Shift-click objects and use Align and Distribute. Give axis labels and legends room. Use the same group colours throughout; test contrast in grayscale and do not rely on colour alone. Add A–F labels in the vector editor after export.
  2. Set the hierarchy. As a starting point, use Arial or Helvetica if installed and accepted by the journal; check for font substitution. Limit the figure to roughly three text sizes (for example panel letters, labels, and ticks/legend), with consistent line weights for equivalent elements. Do not force identical weights on elements serving different purposes. Use true black (#000000) for black text and lines if required.
  3. Check physical size. A maximum width around 180 mm is a useful two-column starting point, not a universal rule. Check the target journal's exact dimensions and minimum text size: commonly 6–8 pt, but requirements vary. Measure type after final cropping and scaling; scaling down also shrinks type and line widths.
  4. Export and finish. Choose PDF or SVG. ktfigure exports the full A4 artboard, not a cropped 180 mm figure; crop the whitespace in a vector editor, set the final physical width without distorting the aspect ratio, and add text and arrowheads there. Solid shapes export, but verify styling; dashed lines and arrowheads may not carry over. PNG currently omits annotations and is exported at 96 dpi, so it is not a publication-resolution substitute.
  5. Inspect the actual file. View the final export at 100% of its physical print size for legibility, then zoom in to check edges and any embedded raster elements for pixelation; zoom out to check the visual balance. If a journal requires raster output, export at its specified dimensions and resolution from the finished vector file: 180 mm at 300 dpi is about 2126 pixels wide. Increasing dpi cannot restore detail already lost in a low-resolution image.
  6. Check the evidence. Verify every panel against the source data and the legend: units, n, replicates, uncertainty, colour key, statistical methods and any exclusions. Follow the journal's current artwork and image-manipulation rules.
Export limitation: PDF/SVG export requires at least one plot. Text objects, line arrowheads and dashed shape styling shown on the canvas are not faithfully exported in the current version. Inspect the exported file, then finish these elements in a vector editor.
