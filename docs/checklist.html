Make the comparison fair.

These schematic layouts show design choices, not actual results. The goal is to make the same evidence easier to read, not to make an effect look larger.

Aligned panels, consistent hierarchy, concise labels and deliberate whitespace help readers compare the evidence.

A truncated axis can exaggerate a difference; a bar of means can hide outliers; changing group colours between panels can suggest a false comparison. Choose a scale appropriate to the data, show individual values when feasible, and explain any transformation or axis break.

Final pass / Every figure

Inspect at publication size.

  1. Align and label. In Select mode, Shift-click objects and use Align and Distribute. Give axis labels and legends room. Reuse group colours across panels, check grayscale contrast and do not rely on colour alone. Put panel letters in the same position.
  2. Set the hierarchy. As a starting point, use Arial or Helvetica if installed and accepted by the journal; check for font substitution. Limit the figure to roughly three text sizes (for example panel letters, labels, and ticks/legend), with consistent line weights for equivalent elements. Do not force identical weights on elements serving different purposes. Use true black (#000000) for black text and lines if required.
  3. Check physical size. A maximum width around 180 mm is a useful two-column starting point, not a universal rule. Check the target journal's exact dimensions and minimum text size: commonly 6–8 pt, but requirements vary. Measure type after final cropping and scaling; scaling down also shrinks type and line widths.
  4. Export and finish. Choose PDF or SVG. ktfigure exports the full A4 artboard, not a cropped 180 mm figure; crop whitespace in a vector editor, set the final physical width without distorting the aspect ratio, and add text and arrowheads there. Solid shapes export, but verify styling; dashed lines and arrowheads may not carry over. PNG currently omits annotations and is exported at 96 dpi, so it is not a publication-resolution substitute.
  5. Inspect the actual file. View the final export at 100% of its physical print size for legibility, then zoom in to check edges and embedded raster elements for pixelation; zoom out to check visual balance. If a journal requires raster output, export at its specified dimensions and resolution from the finished vector file: 180 mm at 300 dpi is about 2126 pixels wide. Increasing dpi cannot restore detail already lost in a low-resolution image.
  6. Check the evidence. Verify each panel against the source data and legend: units, sample size, replicates, uncertainty, colour key, statistical methods and exclusions. Follow the journal's current artwork and image-manipulation rules.
ktfigure export limitation: PDF/SVG export requires at least one plot. Text objects, line arrowheads and dashed shape styling shown on the canvas are not faithfully exported in the current version. Inspect the exported file, then finish these elements in a vector editor.

Concept figures / Provenance

Draw the real experiment.

AI-generated illustrations can invent biological structures, labels or relationships and may raise provenance or journal-policy issues. Do not treat generated imagery as scientific evidence. Verify every element with domain expertise and follow the journal's disclosure rules.

For a simple study design or methods workflow, use ktfigure's Rectangle, Line and Text tools to build only the steps and relationships that actually occurred. Keep connector lines out of text areas; use a vector editor to add final labels and arrowheads after export.
